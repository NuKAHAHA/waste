# Smart Waste Astana

Научный программный модуль для Assignment 3 **Software Development and Integration**,
связанный с темой «Разработка цифровой платформы для автоматизации сбора и вывоза мусора в городе Астана».
CSV → проверка данных → анализ → прогноз → приоритеты → рейсы → JSON, CSV и HTML-отчёт.

**Демонстрационные данные синтетические**: 24 вымышленных контейнера, 7 дат, seed=42.
Это не измерения акимата, не реальные адреса и не подтверждение эффективности в Астане.
Агенты используют правила, линейный тренд и эвристику; LLM и нейросетей нет.
Система работает без GPU, API-ключей, Docker и сторонних runtime-библиотек.

## Быстрый запуск на Windows

Установить **Python 3.11 или новее**. Проверить `py -3 --version`.
Если `python --version` выводит только слово `Python`, это может быть псевдоним Microsoft Store:
установить настоящий Python с python.org и открыть новый терминал.

Распаковать архив и открыть терминал в папке, где находится `main.py`:

```powershell
py -3 main.py demo
Start-Process .\results\dashboard.html
py -3 -m unittest discover -s tests -v
```

Если команды `py` нет, но `python --version` показывает номер 3.11+, заменить `py -3` на `python`.
Можно также дважды нажать **run_demo.bat**. Виртуальное окружение и `pip install` для демо не нужны.

Linux / macOS:

```bash
python3 main.py demo
python3 -m unittest discover -s tests -v
```

## Команды и результаты

```powershell
# Пять агентов — полный эксперимент
py -3 main.py demo --seed 42 --bins 24 --days 7 --output results

# Два агента — только текущая заполненность и приоритеты
py -3 main.py demo --agents 2 --output results_basic

# Собственный CSV
py -3 main.py analyze --input data\astana_synthetic.csv --output results_custom

# Сценарий с горизонтом 2 дня и машиной 8 м³
py -3 main.py demo --horizon 2 --truck-capacity 8 --threshold 80 --output scenario_2

py -3 main.py --help
```

## Архитектура и расширение

| Агент | Решение |
| --- | --- |
| AnalysisAgent | Последние значения и скорость роста заполненности |
| ForecastAgent | Прогноз на заданный горизонт, ограниченный 100% |
| PriorityAgent | Отбор по порогу и понятные категории приоритета |
| RouteAgent | Ближайший допустимый контейнер, контроль объёма и возврат в депо |
| EvaluationAgent | MAE прогноза и базового метода на последней дате |

Агенты взаимодействуют через типизированный `Context`. Протокол `Agent` требует
`name` и `run(context)`. Для добавления собственного агента передать его экземпляр в
`run_pipeline(context, agents=[...])`; пример находится в `docs/architecture.md`.
Это последовательная многоагентная архитектура, не распределённая система автономных LLM.

## Формат CSV

```csv
bin_id,district,latitude,longitude,capacity_m3,observed_on,fill_pct
AST-001,Есиль,51.13,71.43,4.0,2026-10-01,50
AST-001,Есиль,51.13,71.43,4.0,2026-10-02,60
AST-001,Есиль,51.13,71.43,4.0,2026-10-03,70
```

Минимум 3 даты на контейнер; последняя дата общая для всех контейнеров.
Метаданные контейнера постоянные, заполненность 0..100%, ёмкость положительная.
CSV должен содержать ровно указанные колонки в данном порядке.
NaN, Infinity, дубликаты bin/date, пустые поля и сбросы заполненности отклоняются.
Реальные данные после вывоза предварительно разделить на отдельные циклы.
Происхождение собственных данных описать отдельно, не выдавать синтетику за муниципальный набор.

## Воспроизводимый эксперимент

Для seed=42: 168 наблюдений, 24 контейнера, 8 к вывозу, 2 рейса.
Ожидаемый MAE линейного прогноза ≈0.646 п.п., persistence ≈7.139 п.п.
Сумма расстояний по прямой ≈35.814 км, объём ≈18.097 м³.
Эти числа относятся только к демонстрационным данным.
Последняя дата исключена из обучения каждого прогноза, затем сравнивается с предсказанием.
Планирование будущего вывоза использует всю доступную историю; это отдельная задача.

## CI и доставка

Корневая `.github/workflows/smart-waste-ci.yml` запускается при push и pull request
с изменениями модуля. Матрица: Ubuntu с Python 3.11 и 3.13, Windows с Python 3.12.
Проверки: компиляция, 30 тестов, запуск демо, сборка ZIP, проверка запуска из ZIP.
После всех успешных проверок ZIP и результаты доставляются как GitHub Actions artifact.
Отдельный workflow `.github/workflows/smart-waste-release.yml` публикует проверенный
ZIP как GitHub Release при добавлении VERSION в main или ручном запуске.
Существующий релиз сохраняется; для нового релиза нужно обновить версию в
pyproject.toml, VERSION, smart_waste/__init__.py и release workflow.
Release workflow формирует PDF с настоящим Times New Roman в Windows перед сборкой ZIP.
Это доставка научного инструмента, не веб-деплой.
Сведения о реальных запусках и ссылки на них находятся в `docs/validation.md`.

## Ограничения

Линейный тренд не моделирует праздники, погоду, сезонность и неизвестные будущие сбросы.
Маршруты используют расстояния по прямой без дорог, пробок и временных окон.
Число рейсов не ограничено длиной смены; контейнер не делится между рейсами.
Жадный алгоритм не гарантирует глобально оптимальный маршрут.
Для эксплуатации нужны реальные данные, дорожный граф, ограничения смены и оценка на нескольких периодах.
