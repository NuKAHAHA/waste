# Обоснование технологий

| Выбор | Причина | Ограничение |
| --- | --- | --- |
| Python 3.11+ | Читаемый исследовательский код, работает на Windows и Linux | Для больших наборов потребуется оптимизация |
| dataclasses и typing | Явные контракты агентов и параметров | Type hints не заменяют runtime-проверки |
| csv, json, math, random | Работа без сторонних runtime-зависимостей | Нет тяжёлой аналитики pandas/NumPy |
| unittest | Автотесты доступны сразу после установки Python | Нет сторонних плагинов pytest |
| HTML и CSS | Офлайн-визуализация в любом современном браузере | Статический снимок результатов |
| Git | История, ветки, возможность воспроизвести версию | Требует дисциплины коммитов |
| GitHub | Публичная публикация, Issues, PR и Actions | Запуски зависят от настроек аккаунта |
| GitHub Actions | Проверки Windows/Linux и доставка ZIP | Runners и Actions могут меняться |
| MIT | Понятные условия повторного использования модуля | Не распространяется на сторонние данные |

В качестве альтернатив рассматривались Go, pandas, NumPy, scikit-learn и LLM API.
Для небольшой вычислительной задачи Python со стандартной библиотекой уменьшает
стоимость установки и делает формулы доступными для проверки. Прогноз и планирование
реализованы явно; модель не требует многочасового обучения или доступа к GPU.
Go остаётся подходящим языком для существующих сервисов платформы, а этот модуль
можно интегрировать через результаты JSON/CSV или позднее через API.

Git — система контроля версий; GitHub — платформа размещения и сотрудничества.
Mercurial также распределённая VCS, SVN использует централизованную модель.
GitHub выбран благодаря публичным репозиториям и встроенному CI для данного задания.
